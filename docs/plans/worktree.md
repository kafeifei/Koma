## 优先项：按 Sandy 桌面合同修正选择器

### 已确认的问题

实施前的选择器把 `main`、`create` 和已有目录路径混在同一个值里，将所有非 `main` 状态都显示为 Worktree 已勾选。

以用户截图中的新建任务 `kind-wolf` 为例：

- 当前目标是已有 Worktree，勾选状态却容易被理解为将新建独立 Worktree。
- 菜单仍显示“基础分支”，但提交路径只有 `create` 才使用该值；在已有目录状态下选择分支不生效。
- 取消勾选会导航到项目根目录的输入页，再次勾选则变成创建另一个 Worktree；这不是单纯切换隔离模式。
- “主分支”实际表示项目根目录，操作没有执行 Git checkout，文案混淆了目录与分支。
- “工作区…”子菜单和已有 Worktree 列表来自另一套目录选择语义，不符合 Sandy 桌面的独立分支控件与 Worktree 复选框结构。

涉及边界：[选择器](../../packages/app/src/components/prompt-workspace-selector.tsx)、[新任务工作区控制器](../../packages/app/src/pages/new-session/new-session-workspace-controller.ts)、[首次提交](../../packages/app/src/components/prompt-input/submit.ts)。

### Sandy 参考与需要明确的差异

参考当前 Sandy Agent Host 桌面路径，不使用 legacy Copilot picker 或手机统一面板代替桌面合同：

- 顺序为「项目／文件夹」「分支」「Worktree 复选框」，分支菜单只负责分支选择。
- Git 项目首次无偏好时默认开启 Worktree，随后沿用用户上次开关选择；分支不作为跨任务通用偏好记忆。
- Worktree 模式选择的分支是新建隔离目录的起点，不表示复用占用该分支的已有 Worktree。
- 已创建任务的目录和隔离配置是已确定的事实，不能由新建控件原地改动。
- Sandy 当前 folder 模式的 Branch 虽可选择，但只写配置，不执行 checkout／switch。这一冗余行为需要在 OpenCode 中明确消除，不能把它描述成真实切换分支。

参考源码：Sandy 的 `agentHostSessionConfigPicker.ts`、`baseAgentHostSessionsProvider.ts`、`platform/agentHost/node/shared/worktreeIsolation.ts`；本次分析未修改 Sandy。

### 当前行为合同（2026-09-07 用户补正）

1. 独立表达来源目录、所选分支、是否创建隔离 Worktree。分支控件和 Worktree 开关不联动，不改变彼此的值、可选状态或显示形式；Worktree 开关不承担目录导航。

6. 沿用[输入保留合同](input-retention.md)：显式切换目录才打开目标目录自己的输入；切换隔离模式不搬运或替换当前输入。待创建 Worktree 在获得真实路径前，输入仍属于来源目录。

## 同轮实施项

以下项目已纳入本轮授权；归档不会隐式合并，管理不会自动接管或回收外部目录：

- **占用覆盖：** 将手动终端／PTY、V2 执行纳入明确的占用合同；外部和脱离 Session 的进程需要单独说明检测能力与边界。
- **本地文件保留：** 区分可重建依赖／产物和需要保留的 Git ignored 文件，例如被忽略的 `.env`；本轮已补齐 ignored 文件保留。
- **历史及孤立目录：** 已补齐未绑定任务识别、旧目录接管和手动清理入口；不默认接管或删除外部目录。
- **管理可见性：** 集中展示目录、分支、关联任务、空间占用及清理状态，补齐失败原因和手动重试入口。
- **成果合回：** 专门的合回和冲突处理体验；保持与归档／回收职责分开，不在归档时隐式合并。
- **V2 生命周期接入：** 补齐任务菜单在 V2 下的能力门控、专用归档／恢复／删除接口和执行占用合同。

## 本轮实现合同与验收记录

### 占用与生命周期

- Core 增加可选目录租约接入口，未安装宿主适配时保持现有行为；Lab 同一后端的 V1、V2 和 PTY 共用 Worktree 生命周期占用表。
- PTY 按启动目录取得租约，关闭／退出／所属 Location 释放时归还；V2 在完整 Session drain 期间持有租约。覆盖 canonical 路径别名与目录包含关系。
- 检测限于本后端记录的占用。外部进程、终端启动后 `cd` 到别处、脱离后端生命周期的子进程不在检测范围内，不宣称全系统进程检测。
- V2 提供 capabilities 与专用 archive／restore／delete 接口；无宿主适配的独立 V2 服务明确报告不支持。UI 以实际能力门控，未知或失败不能当成支持。
- [x] 真实 HTTP／Git 验证 V2 创建、归档回收、目录缺失后的恢复和删除。
- [x] V1／V2 PTY 占用、pending 期间拒绝新终端、关闭后续归档，以及完整 V2 drain 的占用释放。
- [x] V2 前端所有入口能力门控、请求与缓存同步；浏览器回归覆盖不支持、能力失败重试和专用 mutation。

归档后的任务可查看历史，但不再接收新消息、命令或 shell 执行；必须通过恢复入口解除归档后继续。V1、V2 和 Codex 输入的归档检查由所属后端完成，已开始的执行不因归档自动中断。恢复受管目录时，目录重建、保存状态还原及引用清理全部完成后才清除 Session 的归档标记；失败保留归档并允许重试。普通非受管目录和共享目录沿用原有保留规则。

### 文件保留

- 默认保存 Git 可表达的暂存、未暂存、普通未跟踪文件和 ignored 本地内容；`.env`、本地数据库、证书、普通产物目录均不因名称被排除。
- 仅跳过明确可重建依赖／缓存，例如 `node_modules`、`.pnpm-store`、Python 缓存、`.yarn/cache` 与 `.next/cache`；服务层另支持显式保存全部 ignored 内容。
- 管理详情展示保留、跳过、无法保存的明细。符号链接只保存链接本身，不遍历目标；特殊文件、嵌套仓库或读取失败阻止回收并保留现场。
- Git stash 兼容的保存对象增加独立 ignored parent；兼容已有两／三 parent 保存；恢复保护同路径文件，删除目录前复查保存快照与当前文件一致。
- [x] 真实 Git 保存／恢复、ignored-only、空目录、碰撞、部分恢复重试、旧格式和 stash apply 兼容验证。
- [x] 包内 Node 路径同样覆盖本轮 ignored 内容保留。

### 管理与成果合回

- 项目菜单提供集中管理，按 Git 当前清单和后端生命周期记录展示目录、实际分支、关联任务、占用、回收／错误状态；空间与 ignored 明细按需读取。
- 未绑定目录提供显式接管／清理。接管不创建 Session、不改目录或分支；主目录、共享或不属于当前仓库的目录不能接管；接管已有用户分支不赋予删除该分支的所有权。
- Git 的主 worktree 以实际 Git 清单为准，不能把项目第一次打开的目录当成主 checkout。
- 合回先用独立临时 index 和 Git 三方合并计算差异／冲突，包含来源的已提交、未提交和普通未跟踪结果；ignored 内容不作为合回输入。
- 确认时校验来源 HEAD／tree 和目标 HEAD／merged tree 未变化，且两端无后端占用、目标干净且无进行中的 Git 操作。将结果放入主目录暂存区，不隐式提交或移动分支。
- 冲突展示具体文件和差异，逐文件显式选择主目录或 Worktree 的整份版本；不默认选边。选择后重新预览最终结果，确认失败保留预览和文件。过期预览、目标本地文件碰撞或数据无法完整读取时拒绝应用。选择与四个 Git 哈希由 reviewID 绑定，不能绕过二次预览。支持文本、二进制、符号链接、模式和修改／删除冲突；复杂目录／重命名冲突明确拒绝，保留原文件供现有 Git 工具处理。

- [x] 管理／接管／清理／合回的真实 HTTP 和 UI 验证。
- [x] 代码与生成客户端一致性、包级类型检查、会话性能对照、Node 包验证及 diff 审计。

# 扩展管理

设置中的「插件」管理当前服务的 OpenCode 后端插件；「集成」管理当前项目的 MCP 连接。原生 Codex 任务不会自动获得 OpenCode 插件的工具或 hooks。终端 UI 插件不作为桌面 UI 扩展加载；外部生态项目可在发现目录中浏览并前往获取。

## 插件

支持 npm 包名（可带版本）或服务端的本地绝对路径。安装先下载、验证后端入口及声明的 OpenCode 版本范围，记录实际 npm 版本；此步骤不导入插件代码。实例初始化时复用上游插件加载器运行已启用插件。

安装记录、启用配置和每个已加载实例的运行结果分别保存或观察。更改开关、选项或卸载不会销毁正在使用插件的实例：界面显示「待重新加载」，原实例保持现状，后端重新启动后按最新记录加载。新初始化的项目也会读取最新记录。Koma 不自动重启后端。

卸载移除 Koma 的安装记录；保留共享 npm 缓存、本地源文件及插件自行创建的数据、操作系统计划任务等外部资源。当前实例仍持有插件时，该行保留并显示待重新加载。配置文件声明的插件显示为外部管理，不会被设置页覆盖。

插件和后端处于同一进程，继承其文件、网络和命令执行能力；Agent 的工具审批不是插件沙箱。发现目录提供已核实安装方式的包，其余包也可手动添加；是否兼容仍以实际加载结果为准。

## 集成

MCP 连接按服务端解析后的项目目录保存，可配置远程 URL 或本地执行程序、参数；高级选项支持上游 MCP 的环境变量、请求头、OAuth 和超时配置。保存后连接，关闭后断开，移除时关闭客户端并移除该项目记录。已有配置文件中的 MCP 项目只读显示。

项目存在运行中任务时，管理接口拒绝更改连接，返回可重试的冲突状态。空闲检查、连接变更与任务进入运行状态使用同一个项目锁，避免检查完成后恰好有新任务启动。网络连接失败仍保留配置，并显示实际错误，可通过重新启用或保存重试。OAuth 使用已有 MCP 授权流程；移除连接保留授权记录，避免撤销其他项目使用的同名授权。

## 存储与接口

管理记录位于当前 profile 的配置目录下 `koma-extensions.json`，版本为 1。读改写由跨进程锁保护，临时文件写入后原子替换，文件权限为 0600；损坏的记录不会被自动覆盖。现有 `opencode.json/jsonc` 不被修改。

- `/global/extensions/plugins`：查询、安装、修改插件。
- `/global/extensions/plugins/:id`：卸载插件。
- `POST /global/extensions/plugins/remove`：通过 JSON 传递 ID 卸载，支持完整的本地文件 URL；界面采用此入口。
- `/extensions/integrations?directory=...`：查询、保存当前项目连接。
- `/extensions/integrations/:name?directory=...`：移除当前项目连接。

接口使用现有服务认证和目录路由；界面使用所选服务的 URL 与凭据，不固定连接本机。运行状态仅代表响应请求的后端进程，同一 profile 下其他后端的已加载实例会在其下一次加载时采用持久记录。

## 官方资源目录

「插件」和「集成」均提供「发现／已安装」视图。目录读取 OpenCode 官方仓库的英文 Ecosystem 和 MCP 文档源；当前内置快照包含 38 个插件、11 个外部项目、2 组 Agent 配置及 3 个 MCP 示例。它们标记为官方文档收录的社区资源，不代表官方认证或全部兼容 Koma。

首次打开直接返回内置目录或本地缓存；「刷新目录」通过当前后端获取官方源，成功解析两份文档后才原子替换缓存。请求仅访问固定的公共文档 URL，不携带当前服务的认证信息。网络错误、超时、异常文档和过大的响应均保留上一次目录并显示错误。关闭设置或离线不会丢失已缓存资源。中文说明来自官方中文文档的随包快照；英文说明发生变化或缺少翻译时显示当前原文。

资源身份由类型和项目 URL 组成，允许重名项目。`catalog.recipes.json` 逐项绑定发布者的真实安装方式，覆盖当前 38 项：28 个 npm 插件、7 个源码插件、1 份规则、1 项已内置认证、1 个需在 OCX 中配置的完整工作环境。包名以发布者文档及实际 npm 元数据为依据，不从目录显示名猜测。

npm 安装复用原有插件管理器并锁定实际下载版本。源码安装覆盖 background-agents、notify、worktree 及未发布 npm 包的 Morph Fast Apply、Notificator、Firecrawl、Tavily；下载固定 Git commit 的文件，逐个校验 SHA-256，在独立缓存目录中保留相对路径并安装依赖，安装阶段不执行插件或依赖安装脚本。失败会清理不完整目录，不留下已安装记录。源码插件同样可关闭、卸载，并显示实际运行状态；已加载代码引用的缓存保留到运行实例结束，不通过卸载强行终止任务。

Shell Strategy 显示「导入规则」，下载规则后通过 OpenCode 原生 `config.instructions` 接入，沿用启停和卸载生命周期。Firecrawl、Tavily 同时携带其技能文件。Codex 认证显示「已内置」；完整 OCX Workspace 明确展示工作环境及权限调整范围并提供 OCX 配置入口。API Key、外部 CLI、Zellij 等使用前提显示在对应卡片中。所有安装入口仅证明资源获取与加载方式可用，完整行为仍取决于插件及后端环境；DCP 等插件的 TUI 界面不会显示在 Koma 桌面中。

MCP 目录从官方 Examples 中提取首个远程连接示例，预填名称、地址和 OAuth 需求。用户仍需选定项目并保存连接；没有项目时可以浏览全部目录。文档中的本地命令、密钥、环境变量和其他配置不会自动导入。独立应用、编辑器扩展与 Agent 配置提供获取入口，不能作为 MCP 安装。

- `GET /global/extensions/catalog`：返回随包目录或本地缓存。
- `POST /global/extensions/catalog/refresh`：刷新固定官方源，失败时返回旧目录及 warning。
- `POST /global/extensions/catalog/install`：按目录 ID 安装，服务器查找随包安装配方，不接受客户端提供的下载地址或脚本。
- 缓存：当前 profile 缓存目录下 `koma-extension-catalog.json`；与已安装记录分离。
